# 定时任务拆分设计文档

## 1. 概述

### 1.1 目标

将 `stock-fast-api` 项目中所有 ETL/后台任务相关代码抽离为独立的 `stock-etl-engine` 项目，实现两个服务的**独立部署与扩缩容**。

### 1.2 原则

- 主应用面向客户端的 API 接口（路径、参数、返回值）**不做任何变更**
- ETL 脚本（`app/jobs/*.py`）**零改动**原样搬入新项目
- 双方共享同一个 PostgreSQL 数据库，连接方式各自独立
- 统一通过内网 HTTP 通信完成跨服务任务触发

## 4. 跨服务通信

### 4.1 API 契约

#### ETL 引擎接收端点

```
POST /api/v1/trigger/run
```
主应用 → ETL 引擎：触发执行一个 ETL 任务。

**Request:**
```json
{
  "job_id": 1234,
  "job_name": "daily_kline",
  "biz_date": "2026-06-26",
  "force": false
}
```

**Response:**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "task_id": 1234,
    "status": "accepted"
  }
}
```

```
POST /api/v1/trigger/backfill
```
主应用 → ETL 引擎：触发补历史任务。

**Request:**
```json
{
  "task_id": 5678,
  "symbol": "600519",
  "data_type": "DAILY",
  "start_date": "2026-01-01",
  "end_date": "2026-06-26",
  "force": false
}
```

**Response:**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "task_id": 5678,
    "status": "accepted"
  }
}
```

```
POST /api/v1/trigger/board-sync
```
主应用 → ETL 引擎：同步单只股票板块数据。

**Request:**
```json
{
  "symbol": "600519",
  "trade_date": "2026-06-26"
}
```

```
POST /api/v1/trigger/board-sync-batch
```
主应用 → ETL 引擎：批量同步板块数据。

**Request:**
```json
{
  "symbols": ["600519", "000858"],
  "trade_date": "2026-06-26"
}
```

```
GET /api/v1/trigger/health
```
健康检查（供主应用判断 ETL 引擎是否在线）。

#### 认证

内网通信，通过环境变量 `ETL_ENGINE_API_KEY` 配置共享密钥：
- 主应用在所有请求头中附加 `X-API-Key: <shared-key>`
- ETL 引擎在校验中间件中验证该 Header

### 4.2 错误处理

- ETL 引擎同步响应（非后台执行）：立即返回 `{"code": ? , "message": "error detail"}`
- ETL 引擎后台执行：`job_id` 已在主应用提前创建，ETL 引擎执行完成后调用 `update_job_run()` 写回状态
- 网络超时/不可达：主应用记录错误并返回 `500`，前端可知触发失败
- 主应用配置重试（`tenacity`）：连接失败时最多重试 2 次，间隔 1 秒

### 4.3 服务发现 / 地址配置

主应用通过环境变量 `ETL_ENGINE_URL` 配置 ETL 引擎地址：

```
ETL_ENGINE_URL=http://etl-engine:8082/api/v1/trigger
```

开发环境可配置为 `http://localhost:8082/api/v1/trigger`。

## 5. 任务状态跟踪（job tracking）

### 5.1 流程

拆分后任务状态仍统一记录在 `etl_job_run` 表和 `etl_backfill_task` 表中，双方共享同一个 PostgreSQL 数据库。

**手动触发流程：**

```
主应用                     ETL 引擎                  数据库
  │                          │                        │
  ├─ init_job_run() ─────────┼──────────────────────► INSERT etl_job_run
  │                          │                        │
  ├─ POST /trigger/run ─────►│  (接收请求)             │
  │   {job_id, job_name...}  │                        │
  │                          ├─ job_service.          │
  │                          │   run_job_task()       │
  │                          │     │                  │
  │                          │     ├─ 执行 ETL 脚本    │
  │                          │     ├─ update_job_run  │──► UPDATE status
  │                          │     │  (COMPLETED/     │
  │                          │     │   FAILED)        │
  │                          │     └─ add_log()       │──► INSERT log
  │                          │                        │
  │  (返回 accepted)         │  (异步执行)             │
```

**定时触发流程：**

```
ETL 引擎 APScheduler         数据库
    │                          │
    ├─ is_trade_day() ───────► SELECT dwd_trade_calendar
    ├─ init_job_run() ───────► INSERT etl_job_run
    ├─ 执行 ETL 脚本           │
    ├─ update_job_run() ─────► UPDATE etl_job_run
    └─ add_log() ────────────► INSERT etl_job_run_log
```

### 5.2 并发安全

双方都可能写入 `etl_job_run` 和 `etl_backfill_task`：
- `init_job_run()` 是 INSERT，天然无冲突（不同 job_id）
- `update_job_run()` 是单行 UPDATE，PostgreSQL 行级锁保证安全
- 定时任务和手动触发不可能同一时间跑同一个 job（不同 job_id），无需额外处理

## 6. 数据库连接

### 6.1 连接方式对比

| 维度 | 主应用 | ETL 引擎 |
|------|--------|----------|
| 驱动 | SQLAlchemy `engine` + `SessionLocal` | 原生 `psycopg2.connect()` |
| 连接池 | 10/20 连接池 | 无池，每次任务新开连接 |
| 配置源 | `pydantic-settings` 读 `.env` | `os.environ` 直接读取 |

### 6.2 ETL 引擎配置变更

`scheduler.py` 中的 `is_trade_day()` 当前依赖 `app.core.db.engine`，需要改为直接使用原生 `psycopg2` 连接：

```python
# 改造前
from app.core.db import engine
from sqlalchemy import text
with engine.connect() as conn:
    conn.execute(text("SELECT ..."))

# 改造后
import psycopg2
conn = psycopg2.connect(**DB_CONFIG)
cursor = conn.cursor()
cursor.execute("SELECT ...")
```

这与 `app/jobs/*.py` 中的连接方式完全一致，无需额外依赖。

### 6.3 ETL 引擎 config 设计

```python
# app/core/config.py（精简版）
import os

DB_CONFIG = {
    "host": os.environ.get("DB_HOST", "localhost"),
    "port": int(os.environ.get("DB_PORT", 5432)),
    "dbname": os.environ.get("DB_NAME", "stock_cache_system"),
    "user": os.environ.get("DB_USER", "postgres"),
    "password": os.environ.get("DB_PASSWORD", ""),

LOG_DIR = os.environ.get("SYNC_LOG_DIR", "/app/logs")

```

### 7.2 修改的文件

#### `app/main.py`

- 移除 `from app.scheduler import create_scheduler, acquire_scheduler_lock` 及相关 import
- 移除 `startup_event` 中的 `acquire_scheduler_lock()` / `scheduler.start()` 逻辑
- 移除 `shutdown_event` 中的 `scheduler.shutdown()` / `release_scheduler_lock()` 逻辑

#### `stock-fast-api/app/core/config.py`

- 新增 `ETL_ENGINE_URL` 和 `ETL_ENGINE_API_KEY` 配置项

#### `app/routers/jobs.py`

所有 `background_tasks.add_task()` 调用的函数体（`_run_sync` 等）改为 HTTP 调用 ETL 引擎：

```python
# 改造前
def _run_sync():
    from app.jobs.sync_trade_calendar import sync_trade_calendar
    count = sync_trade_calendar(start_date=start_date, end_date=end_date)
    service.update_job_run(job_id, "COMPLETED", rows_written=count)
background_tasks.add_task(_run_sync)

# 改造后
import httpx
resp = httpx.post(
    f"{settings.ETL_ENGINE_URL}/run",
    json={"job_id": job_id, "job_name": "trade_calendar_sync",
          "biz_date": end_date, "params": {"start_date": start_date, "end_date": end_date}},
    headers={"X-API-Key": settings.ETL_ENGINE_API_KEY},
    timeout=5,
)
```

特殊说明：
- 非阻塞触发：`background_tasks.add_task` 仍保留，但内部逻辑改为 HTTP 调用而非直接 import job
- 「无 job 追踪」的端点（如 `/sync-daily`）直接在 BackgroundTasks 中 HTTP 调用
- 「有 job 追踪」的端点先 `init_job_run()` 写入 DB，再将 job_id 传给 ETL 引擎

#### `app/routers/backfill.py`

POST /run：
- 先 `BackfillRepository.run_backfill()` 创建任务记录（不变）
- `_run_backfill` 内部改为 HTTP 调用 ETL 引擎 `POST /trigger/backfill`

#### `app/routers/boards.py`

POST /sync 和 POST /sync/batch：
- 改为 HTTP 调用 ETL 引擎 `POST /trigger/board-sync` 或 `POST /trigger/board-sync-batch`

## 8. ETL 引擎项目详情

### 8.1 main.py

```python
from fastapi import FastAPI
from app.core.config import DB_CONFIG
from app.scheduler import create_scheduler

app = FastAPI(title="A股ETL引擎", version="1.0.0")

# API 密钥校验中间件
from app.middleware.auth import verify_api_key
app.middleware("http")(verify_api_key)

# 注册 trigger 路由
from app.routers import trigger
app.include_router(trigger.router, prefix="/api/v1/trigger")

# 调度器生命周期
scheduler = None

@app.on_event("startup")
async def startup():
    global scheduler
    # 文件锁（多 worker 保护）
    scheduler = create_scheduler()
    scheduler.start()

@app.on_event("shutdown")
async def shutdown():
    global scheduler
    if scheduler:
        scheduler.shutdown()
```

### 8.2 requirements.txt

```txt
# Web 层
fastapi
uvicorn[standard]
pydantic

# 数据库访问（services/repositories 用 SQLAlchemy，jobs/*.py 用原生 psycopg2）
sqlalchemy
psycopg2-binary

# 定时调度
apscheduler

# 数据源
baostock
efinance

# 数据处理

# 工具
python-dotenv

```

注意：相比主应用，**移除**了 `pyjwt`（无 JWT 认证）、`pydantic-settings`（改为直接读 `os.environ`）、`pytest`、`bcrypt`、`httpx`（无需出站 HTTP）、`requests`（ETL 脚本已内置 `urllib`）等与 ETL 无关的依赖。**保留**了 `sqlalchemy`（services/repositories 层仍使用 Session）。

### 8.3 trigger.py 路由

提供 6 个端点：
- `POST /run` — 执行 ETL 任务
- `POST /backfill` — 补历史数据
- `POST /board-sync` — 同步单只股票板块
- `POST /board-sync-batch` — 批量同步板块
- `GET /health` — 健康检查

每个端点使用 `BackgroundTasks` 异步执行，立即返回 `accepted`。

### 8.4 配置优先级

```
环境变量 > .env 文件默认值
```

## 9. Docker 部署

### 9.1 原有部署变更

原 `docker-compose.yml` 中 `stock-fast-api` 服务不再启动自带的 `uvicorn` 工作进程数由 4 降至 2（无需处理长时 ETL 请求，CPU 需求降低）。

### 9.2 新增服务

`docker-compose.yml` 新增 `etl-engine` 服务：

```yaml
etl-engine:
  build:
    context: ./stock-etl-engine
    dockerfile: Dockerfile
  ports:
    - "8082:8082"
  env_file:
    - ./stock-etl-engine/.env
  volumes:
    - etl-logs:/app/logs
  deploy:
    replicas: 1  # 必须为 1，APScheduler 多实例冲突
  restart: unless-stopped
```

### 9.3 网络

两个服务在同一 Docker 网络中，主应用通过服务名 `etl-engine:8082` 访问 ETL 引擎。

## 11. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 网络超时导致任务未触发 | 数据缺失 | 主应用配置 `tenacity` 重试；ETL 引擎每日定时兜底 |
| 两服务写入 DB 冲突 | 数据异常 | 明确读写边界，`etl_job_run` 双方都可写，但不同 job_id |
| ETL 引擎重启丢失正在运行的 job | 部分数据丢失 | ETL 任务天然支持断点续传（`etl_checkpoint` 表） |
| APScheduler 多实例冲突 | 重复执行 | 文件锁机制保留（已在 scheduler.py 中实现） |
| 服务升级顺序 | 短期 API 不可用 | 先部署 ETL 引擎，再部署主应用 |
