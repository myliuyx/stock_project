# 定时任务使用文档

> 本文档描述系统的定时任务配置、任务列表、手动触发方式及日志查看。
>
> **架构说明**：定时调度已由 `stock-etl-engine`（独立 ETL 引擎服务）承担，不再集成在 `stock-fast-api` 中。旧版 `stock-fast-api/app/scheduler.py` 已删除，所有调度逻辑现位于 `stock-etl-engine/app/scheduler.py`。ETL Engine 通过 Docker 对外暴露端口 **8001**（内部通信端口 **8082**）。

---

## 1. 定时任务列表

`stock-etl-engine` 共注册 6 个活跃定时任务 + 2 个已暂停，均通过 APScheduler 调度（北京时间）：

### 活跃任务（ACTIVE）

| 任务 ID | 名称 | Cron 时间 | 执行条件 | 说明 |
|---------|------|----------|---------|------|
| `new_ipo_board_sync` | 新股板块增量同步 | Mon-Fri **17:10** | 必须是交易日 | 查询近7天上市新股，获取其所属板块写入 `dwd_board_master` + `dwd_board_relation`（基于 efinance） |
| `security_master_sync` | 股票主数据同步 | Mon-Fri **17:30** | 必须是交易日 | 同步全市场股票主数据（名称/行业/状态）到 `dwd_security_master` |
| `daily_stock_sync` | 日线行情同步 | Mon-Fri 19:00 | 必须是交易日 | 同步全市场日线行情到 `dwd_stock_daily` |
| `factor_compute` | 技术因子计算 | **Mon-Fri 23:00** | 必须是交易日 | 计算 MA、RSI、MACD 等指标到 `dwd_stock_factor_daily` |
| `selection_mart` | 选股宽表构建 | **Mon-Fri 23:30** | 必须是交易日 | 汇总行情+因子+财务到 `mart_stock_selection_daily` |
| `cleanup_logs` | 日志清理 | 每天 00:05 | 无 | 清理 `/app/logs` 下超过 3 天的 `.log` 文件 |

### 已暂停任务（PAUSED）

> **注**：以下任务在 `scheduler.py` 中被注释掉，可通过手动触发接口调用。

| 任务 ID | 名称 | Cron 时间 | 说明 |
|---------|------|----------|------|
| `adjust_factor_sync` | 复权因子同步 | Mon-Fri 20:00 | 同步全市场复权因子到 `dwd_stock_adjust_factor` |
| `financial_indicator_sync` | 财务指标同步 | Mon-Fri 21:30 | 增量同步财务指标到 `dwd_stock_financial_indicator`（按当前季度） |

**交易日判断**：查询 `dwd_trade_calendar` 表，`is_open = true` 且 exchange = 'SH' 时视为交易日。非交易日自动跳过。

## 2. 定时任务执行流程

每个交易日，`stock-etl-engine` 中的数据按以下顺序流转（北京时间）：

```
17:10 新股板块增量同步
  └─ 来源: efinance
  └─ 目标表: dwd_board_master + dwd_board_relation
  └─ 依赖: 无

17:30 股票主数据同步
  └─ 来源: Baostock
  └─ 目标表: dwd_security_master
  └─ 依赖: 无（盘前执行，获取最新股票状态）

19:00 日线行情同步
  └─ 来源: Baostock
  └─ 目标表: dwd_stock_daily
  └─ 依赖: 无

23:00 技术因子计算
  └─ 来源: 基于 dwd_stock_daily 计算
  └─ 目标表: dwd_stock_factor_daily
  └─ 依赖: 日线同步完成

23:30 选股宽表构建
  └─ 来源: dwd_stock_daily + dwd_stock_factor_daily + dwd_stock_financial_indicator + dwd_board_relation
  └─ 目标表: mart_stock_selection_daily
  └─ 依赖: 因子计算完成

次日 00:05 日志清理（独立任务，无依赖）
```

> **已暂停任务**：复权因子同步 (20:00) 和财务指标同步 (21:30) 当前处于 PAUSED 状态，不自动执行，但可通过下方手动触发接口调用。

## 3. 手动触发接口

以下 HTTP 端点定义在 `stock-fast-api/app/routers/jobs.py`。每个端点内部调用 JobService.trigger_etl()，通过 HTTP 将请求转发到 `stock-etl-engine`（Docker: :8001 / 内网: :8082）的 `/run` 接口执行任务。

### 3.1 日线同步

```bash
POST /api/v1/jobs/sync-daily?trade_date=2026-04-30&force_restart=false
```

- `trade_date`：指定交易日期，不传默认今天
- `force_restart`：true 表示清除断点从头开始

### 3.2 财务指标同步（当前 PAUSED，可手动触发）

```bash
POST /api/v1/jobs/sync-financial?year=2026&quarter=1
# 全量范围同步
POST /api/v1/jobs/sync-financial?start_year=2021&end_year=2026
```

- 指定年份和季度，不传默认当前季度
- `start_year` + `end_year`：批量跨年度补数

### 3.3 技术因子计算

```bash
POST /api/v1/jobs/sync-factor?trade_date=2026-04-30&full=false
```

- `full`：true 表示全量重算最近 2 年
- 不传 `trade_date` 默认计算最近 5 个交易日

### 3.4 选股宽表构建

```bash
POST /api/v1/jobs/sync-selection?trade_date=2026-04-30&full=false
```

- 参数同技术因子计算

### 3.5 复权因子同步（当前 PAUSED，可手动触发）

```bash
POST /api/v1/jobs/sync-adjust-factor?start_year=2010&end_year=2026
```

- `start_year`：起始年份，默认 2010
- `end_year`：结束年份，不传则用今年

### 3.6 新股板块增量同步

```bash
POST /api/v1/jobs/sync-new-ipo-boards?days=7
```

- `days`：查询近 N 天新股（默认 7，最大 30）

### 3.7 全量板块关系同步

```bash
POST /api/v1/jobs/sync-board-relation-full
```

- 对 `dwd_security_master` 中所有上市股票重新获取板块数据

### 3.8 通用触发接口（按 job_name 路由）

```bash
POST /api/v1/jobs/run
Content-Type: application/json

{ "job_name": "daily_kline_sync", "biz_date": "2026-04-30", "force": false }
```

支持的 `job_name`：

| job_name | 对应任务 |
|----------|---------|
| `trade_calendar_sync` | 交易日历同步 |
| `daily_kline_*` | 日线行情同步 |
| `financial*` | 财务指标同步 |
| `factor_compute` | 技术因子计算 |
| `selection_mart` | 选股宽表构建 |
| `adjust_factor_sync*` | 复权因子同步 |
| `new_ipo_board_sync` | 新股板块增量同步 |
| `board_relation_full_sync` | 全量板块关系同步 |

## 4. 补历史任务

针对单只股票补充历史数据，通过 backfill 接口：

```bash
POST /api/v1/backfill/run
Content-Type: application/json

{
  "symbol": "600519.SH",
  "data_type": "DAILY",
  "start_date": "2020-01-01",
  "end_date": "2024-12-31",
  "force": false
}
```

**`data_type` 可选值**：

| 值 | 说明 | 对应目标表 |
|----|------|-----------|
| `DAILY` | 日线行情 | dwd_stock_daily |
| `FINANCE` | 财务指标 | dwd_stock_financial_indicator |
| `FACTOR` | 技术因子 | dwd_stock_factor_daily |
| `ADJUST_FACTOR` | 复权因子（暂未实现） | dwd_stock_adjust_factor |

查询补历史状态：

```bash
GET /api/v1/backfill/status/{task_id}
```

```bash
GET /api/v1/jobs?page=1&page_size=20&status=FAILED&biz_date=2026-04-30
```

### 5.2 任务详情

```bash
GET /api/v1/jobs/{job_id}
```

## 6. 定时任务管理

> **注意**：以下调度配置位于 `stock-etl-engine/app/scheduler.py`，不再在 stock-fast-api 中维护。

### 6.1 查看定时任务状态

启动 ETL Engine 后，日志中会打印：

```
✅ 定时任务已注册: 新股板块增量同步 (Mon-Fri 17:10) + 股票主数据同步 (Mon-Fri 17:30) + 日线行情同步 (Mon-Fri 19:00) + 技术因子计算 (Mon-Fri 23:00) + 选股宽表构建 (Mon-Fri 23:30) + 日志清理 (每天 00:05)
```

### 6.2 修改执行时间

编辑 `stock-etl-engine/app/scheduler.py`，调整 `CronTrigger` 参数：

```python
add_safe_job(
    run_daily_sync, "daily_stock_sync", "日线行情同步",
    trigger=CronTrigger(hour=19, minute=0, day_of_week="0-4", timezone='Asia/Shanghai'),
)
```

### 6.3 禁用定时任务

注释掉对应的 `add_safe_job()` 调用即可。当前已暂停的任务（复权因子同步、财务指标同步）即采用此方式。

### 6.4 端口说明

| 场景 | 端口 | 说明 |
|------|------|------|
| Docker 外部访问 | **8001** | 容器映射端口，供 fast-api 或其他服务调用 |
| 容器内网通信 | **8082** | 容器内部监听端口（由 `ETL_API_PORT` 配置） |

## 7. 日志说明

### 7.1 日志文件

任务执行的日志写入 `/app/logs/` 目录（可通过 `SYNC_LOG_DIR` 环境变量修改）：

```
/app/logs/sync_stock_daily_20260501.log    # 日线同步日志
/app/logs/compute_factor_20260501.log       # 因子计算日志
/app/logs/build_selection_mart_20260501.log # 选股宽表日志
```

### 7.2 数据库日志表

通过 API 查询的日志来自数据库 `etl_job_run_log` 表。日志写入时机：

- 任务创建时
- 批次开始时
- 任务完成时
- 任务失败时

## 8. 断点续传

`sync_stock_daily` 支持断点续传。任务中断后重启，自动从上次位置恢复（通过 `etl_checkpoint` 表记录进度）。

如需强制从头开始：
- 定时任务：修改 `force_restart=True`
- API 触发：`?force_restart=true`
- backfill：请求中 `force: true`
